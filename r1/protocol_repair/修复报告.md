## P0-01：背景候选污染

- 共用实现为 R0 `r0/labels.py`，R1 继续通过带哈希门禁的 `r1/reuse.py` 复用；依赖 manifest 已同步。
- 主规则 `disjoint_gt`：有效候选与全部可用 Known/Unknown/difficult GT 的交集面积均为零才是 Background；仅边界接触、面积为零允许。直接检查几何交集，不引入可调交集比例阈值。
- 原正例规则保持：最大 IoU≥0.5 且最近 GT 非 difficult，按该 GT 身份分为 Known/Unknown；其余有交集但未满足正例规则的候选为 Ambiguous，非有限/退化候选为 invalid。空 GT 图像的有效候选为相对可用标注的背景。非法 GT 几何明确报错，不能据此认证背景。
- 原 `max IoU<0.1` 规则由独立 `iou_only` 配置保留。两个协议都先在副本上裁剪到原图边界再分组，未修改官方模型输出。
- GT-reference 维持“注释 GT＋过滤后随机背景”的构成。其随机提案使用同一共用规则；转为 Ambiguous 的随机提案记录在审计中，不加入背景参考池。注释 GT 的身份仍来自注释本身（difficult 为 Ambiguous）。
- R0 Query、R1 每个 own-layer Query 均使用同一规则。评价新增 `grouping_audit.json`，记录同一候选池在两规则下各组数量、差值与迁移；R1 分层保存 all/selected，selected 仍按唯一 Query 计数。该审计是几何分组，后续特征非有限/ROI 无效会另行排除。

没有计算真实 Unknown AUROC，没有用测试评分选择阈值、误差方向、层或掩码率。

## P1-03：R1 batch / resize / padding 一致性

全部19份当前R1主JSON（原10份＋9份raw）和10份IoU-only对照均固定训练batch=1、提取batch=1。`config_read`拒绝非1的训练或提取batch。
两路径使用同一 `ImageOnlyDataset` 和 `pack_images`：官方确定性 resize（short_side=800/max_size=1333及原舍入）、RGB、相同ImageNet归一化、NestedTensor按批最大H/W补零。
真实batch1缓存帧要求 `resized_hw==padded_hw`；模型内部特征mask和归一化均未改动。

`r1/validate_real.py`保留原hook/官方后处理不变性验证，并增加**延后执行的真实测量**：

1. 同一真实图像batch1重复，逐层核对raw/l2/pre-LN、框、logits、Gaussian distance，固定rtol=1e-5/atol=1e-6。
2. 从前32图中寻找会改变首图padding的同批图像，测量batch1与batch2的逐层max_abs/RMS及allclose结果；找不到时明确失败。
3. batch2仅作差异诊断；正式训练/提取仍固定batch1，不要求batch2相等，也不以合成GroupNorm例子代替实测。

本轮未运行该真实入口，未生成其通过声明。

## P1-07：缓存来源校验

诊断和重建评价都先通过 `FrameReader(cache, config)` 核验来源，在来源不符时不会继续计算指标、读取重建权重或创建评价输出：

- split角色、split文件名及当前文件字节SHA256；即使集合相同但文件顺序/重复行改变也拒绝。
- manifest图像ID集合、当前split完整去重集合、index实际集合一致；拒绝重复ID/文件、计数不符、缺帧和不安全路径。
- 数据根目录、resize、训练/提取batch、seed、归一化、padding、层策略及相关提取/预处理/模型源码SHA256。
- 冻结B0 checkpoint路径及文件SHA256；重建评价继续要求重建权重baseline SHA匹配。
- synthetic标志一致；每帧继续验证实际图像ID、层/Query结构及真实batch1 padding。
- Writer结束时核对实际提取集合与请求split一致，部分提取不能标为complete。结果summary保留完整cache provenance。

逐帧损坏仍在流式读取时立即报错；可能保留未完成的CSV，但不会产生有效summary或静默报告成功。
旧缓存缺来源信息或来自batch2时必须重新提取；不能通过人工补写manifest将其认证为batch1缓存。
